## 2. Три трека (выберите один или объедините)

### Трек A. GoGPT end-to-end — «я понимаю, как устроена модель»

**Что строим:** полный жизненный цикл своей модели из L0, на чистом Go.

```
 корпус ──► tokenizer.Train ──► gpt/train (pretrain) ──► SFT + LoRA (L13) ──► int8-квантизация (L12)
                                                                                      │
   evals-отчёт ◄── llm.OpenAICompatible ◄── serve: /v1/chat/completions, continuous batching (L14)
```

| Этап | Пакеты | Критерий приёмки |
|---|---|---|
| 1. Данные | `tokenizer`, скрипт загрузки | ≥ 5 МБ текста, BPE 4–8k, round-trip-тест на всём корпусе |
| 2. Pretrain | `gpt`, `optim` | val loss ниже MLP-LM из L4 и ниже n-gram из L2, кривая обучения в CSV |
| 3. SFT | `gpt` (loss mask), LoRA | модель отвечает в формате шаблона на ≥ 80 % тестовых промптов |
| 4. Квантизация | `weights` | int8: Δperplexity < 2 %, размер ×4 меньше, tokens/s измерены |
| 5. Serving | `serve` | OpenAI-совместимый API, streaming; нагрузочный тест: TTFT p50/p95, throughput |
| 6. Оценка | `evals` | eval-набор ≥ 50 кейсов, отчёт с bootstrap CI, diff «до SFT / после SFT» |

**Чему учит:** вы своими руками проходите путь «base model → assistant» из L0 и видите, на каком шаге что меняется.

### Трек B. Ассистент по знаниям — «я умею строить продукт на LLM»

**Что строим:** агент, который отвечает на вопросы по вашему репозиторию (алгоритмы, лекции, код)
и умеет запускать тесты.

```
 вопрос ──► agent (L18) ──► tools: rag.Search │ ReadFile │ SearchFiles │ GoTest
              │                      │
              │                 rag.Store (BM25 + HNSW + RRF) по problems/**, ai_engineering/**
              ▼
         llm.Client (Claude API; ретраи, бюджет, кэш промпта)  ──►  ContextManager (L20)
              │
         evals: golden set + LLM-judge + трейсы  ──►  MCP-сервер для Claude Code
```

| Этап | Критерий приёмки |
|---|---|
| 1. Индекс | весь репозиторий проиндексирован; recall@5 ≥ 0.8 на golden set из 50 вопросов |
| 2. Retrieval | сравнение BM25 / dense / hybrid / hybrid+rerank в таблице (recall@5, MRR) |
| 3. Агент | ответы с цитатами `[n]` на источники; бюджет токенов и шагов; трейсы в JSON |
| 4. Безопасность | 10 атак prompt injection через содержимое файлов; доля отражённых атак измерена |
| 5. Evals | faithfulness (LLM-judge с проверкой position bias), стоимость и латентность p50/p95 на вопрос |
| 6. Интеграция | MCP-сервер подключён к Claude Code, демо-сессия записана |

**Чему учит:** это ежедневная работа AI-инженера: retrieval, инструменты, оценка, стоимость, безопасность.

### Трек C. Мини-инференс-движок — «я понимаю, почему инференс дорогой»

**Что строим:** движок, который загружает открытую Llama-подобную модель и обслуживает её эффективно.

| Этап | Критерий приёмки |
|---|---|
| 1. Загрузка | safetensors → `gpt.Model`, логиты совпадают с эталоном до 1e-3 |
| 2. Квантизация | int8 и int4 (group-wise); таблица размер / tokens/s / perplexity |
| 3. KV-cache | paged-аллокатор блоками; фрагментация измерена против непрерывного |
| 4. Батчинг | continuous batching против static: TTFT и throughput при 1, 4, 16, 64 одновременных запросах |
| 5. Prefix caching | radix-дерево по токенам; выигрыш на общем системном промпте |
| 6. Speculative | своя маленькая модель как draft; acceptance rate и ускорение |
| 7. Сравнение | бенчмарк против llama.cpp на той же модели (честно, с разбором разницы) |

**Чему учит:** почему decode упирается в память, сколько стоит каждый токен и где теряется производительность.

### Комбинации

- **A + B:** ассистент работает на вашей собственной модели через `serve`. Качество будет низким, но архитектура
  полностью ваша, и хорошо видно, зачем нужны большие модели.
- **B + C:** ассистент на открытой модели через ваш движок, с переключением на Claude API через
  `WithModelRouter` (L16) для сложных вопросов.

## 3. Как вести проект: инженерная дисциплина

1. **Сначала evals, потом фичи.** До первой строки кода соберите 20–50 кейсов и метрику (L19). Каждое изменение —
   прогон, `Diff`, решение по данным.
2. **Один вертикальный срез за неделю.** Сначала самый тупой сквозной вариант (end-to-end), потом улучшения.
   Пример для трека B: неделя 1 — BM25 + один вызов LLM без агента; неделя 2 — HNSW + RRF; неделя 3 — агент.
3. **Записывайте формы и бюджеты.** Для модели — shape в комментариях; для продукта — токены и $ на запрос.
4. **Журнал решений (ADR).** Короткий файл `DECISIONS.md`: что выбрали, какие были альтернативы, какие цифры
   повлияли на решение.
5. **Повторяемость.** Seeds, версии промптов (`PromptTemplate.Fingerprint`, L16), чекпоинты с конфигом.

### Структура проекта

```
ai_engineering/capstone/
  README.md          # архитектурная диаграмма, как запустить, результаты
  DECISIONS.md       # журнал решений
  evals/             # датасеты кейсов (JSONL) и отчёты
  cmd/               # точки входа
  internal/          # склейка пакетов курса
  bench/             # нагрузочные тесты и бенчмарки
```

## 4. Критерии оценки (рубрика самооценки)

| Критерий | 1 — слабо | 3 — хорошо | 5 — отлично |
|---|---|---|---|
| **Работает end-to-end** | отдельные куски | сквозной сценарий работает | демо + инструкция запуска с нуля |
| **Тесты** | нет | unit-тесты ключевых частей | + интеграционные, `-race`, fuzz там, где парсинг |
| **Измерения** | «вроде быстро» | бенчмарки основных путей | бенчмарки + профили (pprof) + сравнение альтернатив |
| **Evals** | нет | метрика на наборе кейсов | CI, разбивка по тегам, diff между версиями, статистическая значимость |
| **Понимание** | не объясню, почему так | объясню каждую часть | объясню trade-off'ы с цифрами и что сделаю дальше |
| **Документация** | нет | README | README + диаграмма + DECISIONS.md + честный раздел «ограничения» |

Цель — не менее 3 по каждому критерию и 5 хотя бы по двум.

## 5. Итоговый экзамен: 30 вопросов по всему курсу

Отвечайте устно за 1–2 минуты, как на собеседовании. Если на вопрос не получается ответить, вернитесь к лекции в скобках.

**Фундамент**
1. Почему LLM — это «функция следующего токена», и как из неё получается вероятность целого текста? (L0, L2)
2. Выведите, почему делят на √d_k. Что будет, если делить на d_k? (L1)
3. Почему минимизация cross-entropy — это метод максимального правдоподобия? (L2)
4. Что такое perplexity и как её интерпретировать? (L2)
5. Выведите градиент softmax + cross-entropy. Почему он равен p − y? (L3)
6. Чем AdamW отличается от Adam с L2-регуляризацией? Покажите на одном шаге. (L3)
7. Зачем нужна инициализация He/Xavier? Что будет с активациями при σ = 1 в глубокой сети? (L4)

**Трансформер**
8. Как работает BPE? Почему русский текст стоит больше токенов? (L5)
9. Докажите, что в RoPE скалярное произведение зависит только от m − n. (L6)
10. Опишите все shape от (B, T, C) до выхода multi-head attention. (L7)
11. Чем GQA отличается от MHA, и сколько памяти KV-cache это экономит для Llama-3-8B? (L7, L10)
12. Pre-LN против Post-LN: что и почему стабильнее? (L8)
13. Посчитайте число параметров GPT-2 small по формуле. Откуда берётся 12·L·d²? (L8)
14. Чему должен быть равен loss при инициализации и почему? Какие ещё проверки вы делаете в начале обучения? (L8, L9)
15. Что такое gradient accumulation, и почему loss делят на число шагов? (L9)

**Инференс и масштаб**
16. Почему prefill упирается в вычисления, а decode — в память? (L10, L14)
17. Как работают top-p и min-p? Когда temperature = 0 эквивалентна greedy? (L10)
18. Почему speculative decoding не меняет распределение выхода? (L10)
19. Chinchilla: сколько токенов на параметр, и почему Llama-3-8B обучали на гораздо большем объёме? (L11)
20. Сколько байт на параметр нужно при обучении с mixed precision и Adam? Что из этого шардирует ZeRO-3? (L11)
21. Как работает int4-квантизация с группами, и почему она ускоряет decode? (L12)
22. SFT, RLHF, DPO, RLVR: что каждый этап даёт модели? (L13)
23. Как работает LoRA, и сколько параметров она обучает для матрицы 4096 × 4096 при r = 8? (L1, L13)
24. FlashAttention: что такое online softmax, и почему не нужна матрица T × T? (L14)
25. Continuous batching против static: какие метрики меняются и почему? (L14)

**Продукт**
26. Как устроен prompt caching, и как он влияет на порядок частей промпта? (L16, L20)
27. BM25 против dense-поиска: когда что выигрывает? Зачем RRF? (L17)
28. Как устроен агентный цикл? Почему надёжность падает как pⁿ, и что с этим делать? (L18)
29. Как понять, что изменение промпта действительно улучшило систему, а не случайно? (L19)
30. Что такое context rot, и какие стратегии управления контекстом вы знаете? (L20)
