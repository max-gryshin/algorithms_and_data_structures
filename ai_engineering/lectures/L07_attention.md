# L7. Attention полностью: forward, backward, Multi-Head, GQA

> **Цель лекции:** разобрать attention так, чтобы вы могли написать его с нуля, назвать форму каждого тензора и
> вывести backward руками. Начнём с интуиции «мягкого словаря», пройдём forward по шагам с формами
> (B, T, C) → (B, h, T, d) → (B, h, T, T), разберём маски (почему −∞ и что ломается в fp16), **выведем якобиан
> softmax и обратный проход через attention** на примере из двух токенов, затем Multi-Head, MQA/GQA с арифметикой
> KV-cache, стоимость O(T²), induction heads и attention sinks. Отдельный раздел — разбор вашего
> `algorythm/attention` (и первое задание — его исправить).
> Код: `ai_engineering/nn` (`transformer.go`: `CausalSelfAttention`, `CausalMask`).

---

## 1. Зачем это нужно

MLP-LM из L4 видел три символа и упёрся в потолок: чтобы видеть дальше, нужно, чтобы **каждый токен мог взять
информацию из любого предыдущего** — причём сам решал, из какого. Это и делает attention: единственный слой
трансформера, где токены обмениваются информацией. Всё остальное (FFN, нормы) работает с каждым токеном
отдельно.

```
 L6 эмбеддинг+позиция ─► [L7: attention] ─► L8 блок/GPT ─► L9 обучение ─► L10 генерация, KV-cache
                            ▲ вы здесь
```

Инженерно attention — источник почти всех проблем масштабирования: квадратичная стоимость по длине контекста,
KV-cache, который при длинных диалогах занимает больше памяти, чем сама модель, FlashAttention, GQA,
paged attention в vLLM. Всё это мотивируется формулами этой лекции.

## 2. Интуиция: мягкий словарь

**Обычный словарь** (Go `map`): по ключу находим **одно** значение; ключ должен совпасть точно.

```go
v := dict["кот"] // точное совпадение или ничего
```

**Attention** — словарь, где запрос сравнивается со **всеми** ключами, и ответ — **смесь** всех значений,
взвешенная по похожести:

$$\text{ответ} = \sum_j \underbrace{\text{softmax}_j(\mathbf{q}\cdot\mathbf{k}_j)}_{\text{вес } j}\; \mathbf{v}_j$$

Пример: запрос похож на три ключа с баллами [2, 1, 0] → softmax = [0.665, 0.245, 0.090] (L2) → ответ на 66.5 %
состоит из значения первого ключа, на 24.5 % — второго, на 9 % — третьего.

Почему «мягкий»: argmax («взять лучший ключ») не дифференцируем — маленькое изменение q либо ничего не меняет,
либо скачком меняет ответ. Softmax — гладкий argmax (L2), через него проходит градиент, и W_Q, W_K, W_V можно
учить спуском.

**Self-attention:** q, k, v берутся из одной последовательности (каждый токен спрашивает у всех токенов того же
текста). **Cross-attention:** q из одной последовательности, k и v — из другой (декодер переводчика смотрит на
закодированный исходный текст; в диффузионных моделях картинка смотрит на текстовый промпт, L15). В GPT —
только self-attention.

**Зачем три проекции**, а не просто X·Xᵀ: токену-запросу нужно спрашивать о **другом**, чем он сам. «Он» ищет
существительное мужского рода (запрос), а сам предлагает «я местоимение» (ключ), и отдаёт при совпадении
третье — «что вставить в контекст» (значение). Три разные матрицы — три разные роли одного эмбеддинга.

## 3. Forward по шагам, с формами

Обозначения: B — батч, T — длина, C = d_model, h — число голов, d = d_head = C/h. Числа справа — GPT-2 small при
B = 8, T = 1024 (C = 768, h = 12, d = 64).

| # | Шаг | Формула | Форма | GPT-2, B = 8 |
|---|---|---|---|---|
| 0 | вход (residual stream после нормы) | X | (B, T, C) | (8, 1024, 768) |
| 1 | проекции | Q = XW_Q, K = XW_K, V = XW_V | (B, T, C) каждая | 6.3 млн чисел каждая |
| 2 | разбиение на головы | reshape (B, T, h, d) → transpose(1, 2) | (B, h, T, d) | (8, 12, 1024, 64) |
| 3 | (RoPE, если есть — L6) | поворот q и k | (B, h, T, d) | |
| 4 | скоры | S = QKᵀ / √d | (B, h, T, T) | (8, 12, 1024, 1024) |
| 5 | маска | S + M, M = 0 / −∞ | (B, h, T, T) | |
| 6 | softmax по последней оси | A = softmax(S) | (B, h, T, T), строки суммируются в 1 | |
| 7 | смешивание значений | O = A·V | (B, h, T, d) | |
| 8 | склейка голов | transpose(1, 2) → reshape | (B, T, C) | |
| 9 | выходная проекция | Y = O·W_O | (B, T, C) | (8, 1024, 768) |

### 🔍 Формула под лупой: scaled dot-product attention

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}} + M\right) V$$

| Символ | Форма (одна голова) | Смысл |
|---|---|---|
| Q | T × d | строка i — «что ищет» токен i |
| K | T × d | строка j — «что предлагает» токен j |
| QKᵀ | T × T | элемент (i, j) = qᵢ · kⱼ — похожесть (L1: таблица скалярных произведений) |
| √d | число | нормировка: Var(q·k) = d → после деления 1 (вывод в L1, раздел 8) |
| M | T × T | маска: 0 — можно смотреть, −∞ — нельзя |
| softmax | по строке | строка i → распределение «на кого смотрит токен i» |
| ·V | (T × T)(T × d) | строка i результата = взвешенная сумма строк V (L1, «взгляд 2») |

**Шаг 4 в памяти.** Тензор скоров (8, 12, 1024, 1024) — это 100.7 млн чисел = **384 МиБ** в fp32 на **один**
слой. Для backward нужно сохранить A (выход softmax) каждого из 12 слоёв — 4.5 ГиБ только на матрицы внимания.
Отсюда FlashAttention (раздел 9).

**Шаги 2 и 8 бесплатны** (почти): reshape — смена формы без копирования, transpose — смена strides (L1, 7.3–7.4).
«Конкатенация голов» из вашего конспекта — это не склейка массивов, а другой взгляд на ту же память. В нашем
autograd `Transpose` делает копию (`Contiguous`), чтобы следующий matmul читал память подряд.

## 4. Маски

### 4.1. Causal-маска: не подглядывать в будущее

Модель обучается предсказывать токен t+1 по токенам ≤ t **на всех позициях сразу** (одна последовательность из
T токенов = T обучающих примеров). Если токен t увидит токен t+1, задача становится тривиальной — скопировать
ответ, — и модель ничему не научится. Поэтому скор (i, j) при j > i заменяют на −∞:

```
          j=0   j=1   j=2               после softmax:
 i=0  [  s₀₀   −∞    −∞  ]              [ 1      0      0    ]
 i=1  [  s₁₀   s₁₁   −∞  ]              [ a₁₀    a₁₁    0    ]
 i=2  [  s₂₀   s₂₁   s₂₂ ]              [ a₂₀    a₂₁    a₂₂  ]
```

Это `nn.CausalMask(tq, tk)`. Она выровнена по **нижнему правому углу**: если запросов меньше, чем ключей (при
генерации с KV-cache в L10 новый токен — один запрос против всех закэшированных ключей), запрос i стоит на
позиции tk − tq + i и видит все ключи до неё включительно. Тест `TestCausalMask`: `CausalMask(1, 3)` — все нули.

### 4.2. Почему −∞, а не «очень маленькое число»

### 🔍 Формула под лупой: маска до softmax

Скоры [2, 1, ×], третий токен надо скрыть:

| Чем маскируем | Скоры | softmax | Утечка в замаскированный |
|---|---|---|---|
| −∞ | [2, 1, −∞] | [0.7311, 0.2689, **0**] | ровно 0: e^{−∞} = 0 |
| −10⁴ | [2, 1, −10⁴] | [0.7311, 0.2689, 0] | e^{−10002} ≈ 0 (underflow в 0) |
| −5 («маленькое») | [2, 1, −3] | [0.7275, 0.2676, **0.0049**] | 0.5 % — модель подглядывает |

**Почему маскируют до softmax, а не обнуляют веса после.** Если обнулить веса после, строка перестанет
суммироваться в 1 — придётся нормировать заново. Маска до softmax делает это автоматически: замаскированные
слагаемые просто выпадают из знаменателя.

**Подвох fp16.** Максимум fp16 — 65 504; числа больше превращаются в inf. Отсюда две ловушки:
1. Константа −10⁹ в fp16 сама становится −∞ — это ещё не страшно, но…
2. …если в строке **все** элементы замаскированы, softmax = 0/0 = **NaN**, и NaN расползается по всей модели за
   один шаг. Так бывает с padding-маской (ниже) для строк-«пустышек».

Поэтому на практике берут **конечное** «самое отрицательное число типа» (`torch.finfo(dtype).min`) — тогда
полностью замаскированная строка даёт равномерное распределение вместо NaN, а её выход потом игнорируется. В
нашем коде (fp32, только causal-маска, диагональ всегда видна) честная −∞ безопасна: полностью замаскированных
строк не бывает.

### 4.3. Padding-маска

Батч из последовательностей разной длины дополняют токеном PAD до общей длины. PAD — не текст, на него нельзя
смотреть: маскируют **столбцы** (ключи) PAD-позиций. Строки (запросы) PAD-позиций маскировать не нужно — их выход
просто не попадает в loss (target = −1, `CrossEntropy` его игнорирует). Итоговая маска = causal + padding
(сложение, −∞ + 0 = −∞).

```
 Последовательность: [Кот, спит, PAD]        маска (causal + pad по ключу 2):
                                              [ 0   −∞  −∞ ]
                                              [ 0    0  −∞ ]
                                              [ 0    0  −∞ ]   ← строка PAD: выход не используется
```

При **генерации** батчами промпты дополняют **слева** (left padding), чтобы последние токены всех промптов
стояли на одной позиции и следующий токен генерировался одновременно. Тогда у PAD-запросов слева **все** ключи
замаскированы — это ровно случай NaN из 4.2.

## 5. Backward через softmax: якобиан

### 📐 Математическая справка: производная частного и якобиан

**Частное:** (f/g)' = (f'g − fg')/g². Проверка: (x/(x+1))' при x = 1: (1·2 − 1·1)/4 = 0.25.

**Якобиан** функции из ℝⁿ в ℝⁿ — матрица n × n всех частных производных: J_{ij} = ∂yᵢ/∂xⱼ («как i-й выход
зависит от j-го входа»). Цепное правило для векторов (L3): если L зависит от **y**, то
∂L/∂xⱼ = Σᵢ (∂L/∂yᵢ)·J_{ij}, то есть dx = Jᵀ·dy.

### 🔍 Вывод: якобиан softmax

aᵢ = e^{sᵢ}/Σ, где Σ = Σₖ e^{sₖ}. Производная по sⱼ — по правилу частного, f = e^{sᵢ}, g = Σ, ∂Σ/∂sⱼ = e^{sⱼ}.

- **i = j:** f' = e^{sᵢ}. ∂aᵢ/∂sᵢ = (e^{sᵢ}Σ − e^{sᵢ}e^{sᵢ})/Σ² = aᵢ − aᵢ² = aᵢ(1 − aᵢ).
- **i ≠ j:** f' = 0 (числитель от sⱼ не зависит). ∂aᵢ/∂sⱼ = (0 − e^{sᵢ}e^{sⱼ})/Σ² = −aᵢaⱼ.

Оба случая одной формулой (δᵢⱼ = 1 при i = j, иначе 0):

$$J_{ij} = \frac{\partial a_i}{\partial s_j} = a_i(\delta_{ij} - a_j), \qquad J = \text{diag}(\mathbf{a}) - \mathbf{a}\mathbf{a}^\top$$

**Числа.** **a** = [0.25, 0.75] (это softmax от [0, ln 3]):

$$J = \begin{pmatrix} 0.25 - 0.0625 & -0.1875 \\ -0.1875 & 0.75 - 0.5625 \end{pmatrix} = \begin{pmatrix} 0.1875 & -0.1875 \\ -0.1875 & 0.1875 \end{pmatrix}$$

Смысл: увеличим s₁ — вес a₁ растёт, a₂ падает на столько же (сумма всегда 1, поэтому строки J суммируются в 0).

### 🔍 Вывод: dS = A ⊙ (dA − rowsum(dA ⊙ A))

J симметрична, поэтому dS = Jᵀ·dA = J·dA. Покомпонентно:

$$dS_j = \sum_i dA_i\, a_i(\delta_{ij} - a_j) = a_j\,dA_j - a_j \sum_i dA_i\, a_i = a_j\Big(dA_j - \underbrace{\sum_i dA_i a_i}_{c}\Big)$$

Для матрицы A (каждая строка — свой softmax) то же самое построчно:

$$\boxed{dS = A \odot \big(dA - \text{rowsum}(dA \odot A)\big)}$$

| Часть | Смысл |
|---|---|
| ⊙ | поэлементное произведение |
| rowsum(dA ⊙ A) | для каждой строки одно число c = Σⱼ dA_{ij}a_{ij} — «средний» градиент по распределению |
| dA − c | насколько градиент позиции j лучше среднего |
| A ⊙ (…) | умножаем на вес: позиции с весом 0 (в т. ч. замаскированные) градиента не получают |

**Числа.** **a** = [0.25, 0.75], dA = [1, −1]: c = 0.25·1 + 0.75·(−1) = −0.5.
dS = [0.25·(1 + 0.5), 0.75·(−1 + 0.5)] = [**0.375**, **−0.375**]. Через матрицу: J·[1, −1] = [0.1875 + 0.1875,
−0.1875 − 0.1875] = [0.375, −0.375] ✓.

**Почему так, а не через матрицу J.** J для строки длины T — это T × T чисел; для всей матрицы скоров — T³ на
голову. Формула в рамке — O(T) на строку: одна сумма и поэлементные операции. Это `autograd.Softmax`
(L4, его backward написан именно так).

**Полезное следствие:** сумма каждой строки dS равна нулю: Σⱼ aⱼ(dAⱼ − c) = c − c·Σⱼaⱼ = c − c = 0. Это
«градиентная» версия того, что softmax не меняется от прибавления константы ко всей строке (L2).

## 6. Backward через attention целиком

Граф одной головы (без маски, для простоты):

```
 Q ─┐
    ├─► S = QKᵀ/√d ─► A = softmax(S) ─┐
 K ─┘                                  ├─► O = A·V ─► L
                                   V ──┘
```

Идём с конца, на каждом шаге — правило matmul из L3 (dA = dC·Bᵀ, dB = Aᵀ·dC):

| Шаг | Формула | Форма (одна голова) |
|---|---|---|
| O = A·V | dA = dO·Vᵀ,  dV = Aᵀ·dO | (T, T), (T, d) |
| A = softmax(S) | dS = A ⊙ (dA − rowsum(dA ⊙ A)) | (T, T) |
| S = QKᵀ/√d | dQ = dS·K/√d,  dK = dSᵀ·Q/√d | (T, d), (T, d) |

(Для S = QKᵀ: «B» — это Kᵀ, поэтому dQ = dS·(Kᵀ)ᵀ = dS·K, а d(Kᵀ) = Qᵀ·dS, т. е. dK = dSᵀ·Q.)

### Числовой пример: «it / works» из вашего конспекта

Q = [[0, 1], [2, 0]], K = [[1, 0], [0, 2]], V = [[2, 0], [0, 6]], d = 2, √d = 1.4142.
Пусть L = o₁₁ + o₂₂ — то есть dO = [[1, 0], [0, 1]] (в реальной сети dO приходит сверху; здесь выбираем
простой).

**Forward.**
```
 QKᵀ = [[0, 2], [2, 0]]                     (посчитано в L1, раздел 5)
 S   = QKᵀ/√2 = [[0, 1.4142], [1.4142, 0]]
 A   = softmax по строкам:
       строка it:    [1, e^1.4142 = 4.113] / 5.113 = [0.1956, 0.8044]
       строка works: [0.8044, 0.1956]
 O   = A·V:  it    = 0.1956·[2, 0] + 0.8044·[0, 6] = [0.3911, 4.8266]
             works = 0.8044·[2, 0] + 0.1956·[0, 6] = [1.6089, 1.1734]
 L   = 0.3911 + 1.1734 = 1.5646
```

В конспекте эти веса записаны как 0.19 / 0.81 — округление точных 0.1956 / 0.8044.

**Backward.**
```
 dV = Aᵀ·dO = Aᵀ                  = [[0.1956, 0.8044], [0.8044, 0.1956]]
 dA = dO·Vᵀ = Vᵀ                  = [[2, 0], [0, 6]]
 c  = rowsum(dA ⊙ A):  строка it:    2·0.1956 + 0·0.8044 = 0.3911
                       строка works: 0·0.8044 + 6·0.1956 = 1.1734
 dS = A ⊙ (dA − c):
   it:    [0.1956·(2 − 0.3911), 0.8044·(0 − 0.3911)] = [ 0.3146, −0.3146]
   works: [0.8044·(0 − 1.1734), 0.1956·(6 − 1.1734)] = [−0.9439,  0.9439]
 dQ = dS·K/√2:
   it:    [0.3146·1, −0.3146·2]/1.4142   = [ 0.2225, −0.4450]
   works: [−0.9439·1, 0.9439·2]/1.4142   = [−0.6675,  1.3349]
 dK = dSᵀ·Q/√2:
   k_it:    (0.3146·[0,1] + (−0.9439)·[2,0])/1.4142 = [−1.3349, 0.2225]
   k_works: (−0.3146·[0,1] + 0.9439·[2,0])/1.4142   = [ 1.3349, −0.2225]
```

Строки dS суммируются в ноль ✓ (следствие из раздела 5). Все числа совпадают с конечными разностями
(проверено скриптом с ε = 10⁻⁶) и закреплены тестом `TestAttentionBackwardLectureExample`.

**Смысл знаков** (привычка «проверить знак смыслом» ловит половину ошибок в выводах). L = o_it,1 + o_works,2,
а o_it,1 = 2·a(it→it) — вклад v_it = [2, 0]. Чтобы **уменьшить** L, it должен меньше смотреть на себя и больше —
на works. Так и есть: dS_it = [0.3146, −0.3146], шаг спуска s ← s − η·dS **уменьшает** s(it→it) и **увеличивает**
s(it→works). В координатах запроса: q_it ← q_it − η·[0.2225, −0.4450] — вторая координата растёт, первая падает;
k_works = [0, 2] лежит на второй оси, k_it = [1, 0] — на первой, поэтому q_it·k_works растёт, q_it·k_it падает ✓.

### Тот же пример с causal-маской

Маска закрывает (it → works): S = [[0, −∞], [1.4142, 0]] → A = [[1, 0], [0.8044, 0.1956]].
```
 O_it = v_it = [2, 0]              (it видит только себя)
 dS   = [[0, 0], [−0.9439, 0.9439]]
 dQ   = [[0, 0], [−0.6675, 1.3349]]
 dK   = [[−1.3349, 0], [1.3349, 0]]
```

Первая строка dS — нули: у it ровно один видимый токен, вес 1 при любых скорах, градиенту некуда течь.
Строка works — та же, что без маски (works и так видит обоих).

### Неожиданное следствие: bias у W_K бесполезен

Если к ключам прибавить вектор **b** (bias в K = XW_K + b), каждый скор строки i изменится на одно и то же число
qᵢ·**b**. Softmax инвариантен к сдвигу строки → выход не меняется → **градиент по b_K ровно 0** (формально:
dK_bias = Σⱼ dKⱼ ∝ Σⱼ Σᵢ dS_{ij} qᵢ = Σᵢ qᵢ·rowsum(dSᵢ) = 0). У GPT-2 этот bias есть, и он не учится. Наш тест
`TestKeyBiasHasNoGradient` проверяет это, а gradcheck-тесты исключают этот параметр — конечные разности
меряли бы там только шум float32. Это хороший пример, когда **понимание** формулы экономит час отладки
«почему gradcheck падает на одном bias».

## 7. Multi-Head Attention

### 7.1. Зачем головы

Одна голова — одно распределение внимания на токен. Но токену нужно одновременно: найти подлежащее (синтаксис),
предыдущий токен (порядок), упоминание того же объекта раньше (кореференция). Несколько голов = несколько
независимых «запросов» в **разных подпространствах**: голова h использует свои столбцы W_Q, W_K, W_V
(срез d_head = C/h), и её скоры считаются только по этим d_head координатам.

### 🔍 Формула под лупой: MHA

$$\text{head}_h = \text{softmax}\!\left(\frac{Q_h K_h^\top}{\sqrt{d}} + M\right)V_h, \qquad Y = \text{concat}(\text{head}_1, \dots, \text{head}_H)\, W_O$$

| Символ | Форма | Смысл |
|---|---|---|
| Q_h = X·W_Q[:, h·d:(h+1)·d] | (T, d) | столбцы W_Q, относящиеся к голове h |
| head_h | (T, d) | выход головы |
| concat | (T, H·d) = (T, C) | склейка — это reshape (раздел 3) |
| W_O | (C, C) | смешивает выходы голов |

**Стоимость не растёт с числом голов.** Параметры: W_Q, W_K, W_V, W_O — по C × C = **4C²** при любом h.
FLOPs скоров: h голов × 2·T²·d = 2·T²·C — как у одной головы ширины C. Головы делят ширину, а не умножают её.

**Пример (C = 4, h = 2, d = 2).** q токена = [1, 0, 0, 1]: голова 1 видит [1, 0], голова 2 — [0, 1]. Ключ
k = [1, 0, 1, 0]: голова 1 — [1, 0], голова 2 — [1, 0]. Скоры (до √d): голова 1: 1·1 + 0·0 = **1**; голова 2:
0·1 + 1·0 = **0**. Одна голова видит совпадение, другая — нет. Единая голова ширины 4 дала бы одно число
q·k = 1 — сумму, и не смогла бы смотреть «одной головой сюда, другой туда».

## 8. MQA и GQA: KV-cache в разы меньше

### 8.1. Проблема: KV-cache

При генерации (L10) для каждого нового токена нужны K и V **всех предыдущих** токенов во всех слоях — их хранят
в KV-cache, чтобы не пересчитывать. Q нужен только для текущего токена, его не кэшируют.

### 🔍 Формула под лупой: память KV-cache

$$\text{байт на токен} = 2 \cdot L \cdot h_{kv} \cdot d_{head} \cdot \text{bytes}$$

| Множитель | Смысл |
|---|---|
| 2 | K и V |
| L | слоёв |
| h_kv | голов K/V (при MHA = h) |
| d_head | размерность головы |
| bytes | 2 для bf16/fp16 |

**Llama-2-7B** (L = 32, h = h_kv = 32, d_head = 128): 2·32·32·128·2 = **524 288 байт = 512 КиБ на токен**.
Контекст 4096 → 2 ГиБ на последовательность. Батч 32 таких запросов → **64 ГиБ** KV-cache — в 5 раз больше
весов самой модели (12.6 ГиБ). Память, а не FLOPs, ограничивает, сколько пользователей обслуживает GPU (L14).

### 8.2. Решение: делить K/V между головами

- **MQA** (Shazeer, 2019): все h голов запросов используют **одну** голову K/V. h_kv = 1 → кэш в h раз меньше.
  Минус: заметная потеря качества и нестабильность обучения.
- **GQA** (Ainslie et al., 2023): компромисс — h голов запросов делятся на h_kv групп, у каждой группы своя K/V.
  h_kv = h → MHA, h_kv = 1 → MQA.

```
 MHA (h_kv = 4):   q₀ q₁ q₂ q₃        GQA (h_kv = 2):   q₀ q₁ │ q₂ q₃      MQA (h_kv = 1):   q₀ q₁ q₂ q₃
                   k₀ k₁ k₂ k₃                          k₀    │ k₁                          k₀
```

| Модель | h | h_kv | КиБ / токен (bf16) | на полный контекст |
|---|---|---|---|---|
| Llama-2-7B (MHA) | 32 | 32 | 512 | 2 ГиБ (4K) |
| Llama-3-8B (GQA) | 32 | 8 | **128** | 1 ГиБ (8K) |
| Llama-2-70B (GQA, L = 80, d_head 128) | 64 | 8 | 320 | (с MHA было бы 2.5 МиБ / токен) |
| гипотетическая MQA-версия Llama-3-8B | 32 | 1 | 16 | |

Ainslie et al. показали, что GQA с 8 группами по качеству близка к MHA, а по скорости декодирования — к MQA.
Поэтому GQA стала стандартом: Llama 2 70B, все Llama 3, Mistral 7B (32/8).

Параметров тоже меньше: W_K и W_V — (C, h_kv·d) вместо (C, C). У Llama-3-8B: 2·4096·1024 вместо 2·4096² —
экономия 25 млн параметров на слой.

### 8.3. GQA в нашем коде — без копирования K/V

Наивно K/V каждой группы копируют g = h/h_kv раз (`repeat_kv` в коде Llama). Мы используем broadcasting
(L1, 7.5): добавляем ось размера 1, и batched matmul растягивает её сам.

```go
q = autograd.Reshape(q, b, kv, g, t, d) // (B, kv, g, T, d): голова j → группа j / g
k = autograd.Reshape(k, b, kv, 1, t, d) // (B, kv, 1, T, d): ось 1 растянется на g
scores := autograd.MatMul(q, autograd.Transpose(k, 3, 4)) // (B, kv, g, T, T)
```

Backward бесплатен: градиент растянутой оси **суммируется** обратно (правило broadcasting из L3, `reduceTo`) —
каждая K/V-голова получает сумму градиентов от всех g голов своей группы. Это ровно то, что даёт `repeat_kv` +
autograd в PyTorch. Порядок голов совпадает с Llama: голова запроса j использует K/V-голову j / g.

## 9. Стоимость: O(T²)

### 🔍 Формула под лупой: FLOPs одного слоя attention

| Часть | FLOPs (прямой проход) | Как растёт |
|---|---|---|
| проекции Q, K, V, O | 2·T·4C² = 8TC² | линейно по T |
| скоры QKᵀ | 2·T·T·C (h голов × 2T²d) | **T²** |
| A·V | 2·T·T·C | **T²** |

Отношение «квадратичной» части к проекциям: 4T²C / 8TC² = T/(2C). С учётом FFN (ещё 16TC² FLOPs, L8) слой
стоит 24TC² + 4T²C, и attention-матрицы сравниваются с остальным при **T = 6C**:
GPT-2 (C = 768) — T ≈ 4 600; Llama 7B/8B (C = 4096) — T ≈ 24 600. До этих длин основная стоимость — матрицы
весов, после — квадратичный attention.

Пример, GPT-2, T = 1024, один слой: скоры + A·V = 4·1024²·768 = **3.2 GFLOP**, линейные слои
2·1024·12·768² = **14.5 GFLOP**.

**Память** хуже, чем FLOPs: матрица A размером T² на голову. Llama-2-7B, T = 4096, bf16: 32 головы · 4096² · 2 байта =
**1 ГиБ на слой на последовательность** — только чтобы сохранить A для backward.

**Что с этим делают:**
- **FlashAttention** (Dao et al., 2022): считает softmax блоками с «онлайн»-нормировкой, никогда не
  материализует T × T, в backward пересчитывает A. Память O(T), FLOPs те же, но в разы меньше обращений к HBM →
  быстрее. Подробно — L14.
- **Sliding window** (Mistral 7B: окно 4096): каждый токен видит только последние W токенов → O(T·W).
- **Linear attention / SSM** (Mamba и др.): заменяют softmax на что-то, позволяющее O(T). Платят качеством на
  задачах точного поиска в контексте.

## 10. Что делают головы: induction heads и attention sinks

### 10.1. Induction heads

Elhage et al. (2021), Olsson et al. (2022, Anthropic). Механизм in-context копирования:

```
 текст:  … Гарри Поттер … … … Гарри [?]
                 ▲                ▲
   голова 1 (previous-token head): каждый токен записывает «передо мной был X»
   голова 2 (induction head): текущий «Гарри» ищет токен, перед которым был «Гарри» → находит «Поттер»
                               и копирует его → предсказание «Поттер»
```

Нужны **две** головы в **разных слоях**: вторая использует в своих ключах информацию, записанную первой (это
называется K-composition) — поэтому однослойная attention-only модель так не умеет. Olsson et al. показали, что
induction heads появляются **скачком** в определённый момент обучения, и одновременно резко улучшается
in-context learning (на кривой loss виден «бугорок»). Это одна из самых убедительных находок
интерпретируемости: конкретная схема → конкретная способность. Задание 🔴 7 — найти такую голову в вашей
модели из L9 (поле `CausalSelfAttention.Weights` хранит веса последнего прохода).

### 10.2. Attention sinks

Xiao et al. (2023, StreamingLLM): во многих головах обученных LLM огромная доля внимания уходит на **первый
токен** — независимо от его содержания. Объяснение: softmax обязан раздать вес 1; когда голове «нечего
искать», ей нужно куда-то «слить» вес, и первый токен (видимый всем благодаря causal-маске) становится
стоком.

Практическое следствие: если при длинной генерации выбросить из KV-cache старые токены (скользящее окно),
выбросив и первый, — качество обрушивается. StreamingLLM оставляет 4 первых токена + окно последних — и модель
стабильно работает на потоках в миллионы токенов. Связанная идея: добавить в softmax «пустой» вариант
(+1 в знаменатель, «softmax off by one»), чтобы голова могла не смотреть никуда; в некоторых открытых моделях
2025 года для этого есть обучаемый логит-сток в каждой голове.

## 11. Разбор вашего `algorythm/attention`

```go
const dimension = 128 // Llama 2-7B is 4096

func (a *Attention) softmax(query linalg.Matrix) linalg.Matrix {
	scores := linalg.MatMul(query, a.Keys.Transpose())
	scalingFactor := math.Sqrt(dimension)
	scale := scores.Divide(scalingFactor)
	return linalg.MatMul(scale, a.Values)
}
```

Что хорошо: правильный порядок QKᵀ → масштаб → ·V; `Transpose` и `MatMul` в `linalg` корректны; в `linalg` уже
есть `Max`, `Map`, `SubScalar`, `DivScalar`, `Sum`, `MapRows` — ровно всё, что нужно для softmax.

**Проблемы:**

1. **Нет softmax.** Функция называется `softmax`, но экспоненты и нормировки нет: веса — это сырые скоры. Строки
   не суммируются в 1, веса бывают отрицательными, а выход растёт с длиной контекста (сумма T слагаемых вместо
   взвешенного среднего). На примере it/works: скоры [0, 2]/√128 = [0, 0.177] → выход it = 0·[2, 0] +
   0.177·[0, 6] = **[0, 1.06]** вместо правильного **[0.391, 4.827]**.
2. **Масштаб не от тех данных.** `dimension = 128` — константа, а должен быть d_k = `Keys.Cols()` (размерность
   ваших ключей). В примере d_k = 2: даже с настоящим softmax деление на √128 дало бы веса [0.456, 0.544] —
   почти равномерное «размазанное» внимание — вместо [0.196, 0.804]. (И комментарий неточен: 4096 у Llama-2-7B —
   это d_model, а d_head = 128.)
3. **Нет маски** — модель-генератор с таким attention подглядывала бы в будущее.
4. **Нет защиты от переполнения.** Когда появится exp, нужен «вычесть максимум строки» (L2): e^{1000} = +Inf.
5. **Именование:** функция `softmax` делает весь attention; лучше разделить `Weights` (softmax(QKᵀ/√d + M)) и
   `Calculate` (Weights·V) — и тестировать веса отдельно.

// a.Weights *tensor.Tensor — веса последнего Forward, (B, h, T, T)

Forward целиком — каждая строка с формой:

```go
q := split(a.Q.Forward(x), h)  // (B, T, C) → (B, h, T, d)
k := split(a.K.Forward(x), kv) // (B, kv, T, d)
v := split(a.V.Forward(x), kv) // (B, kv, T, d)
if a.Rope != nil {
	q = a.Rope.Apply(q, pos) // поворот на позициях pos..pos+T−1 (L6)
	k = a.Rope.Apply(k, pos)
}
q = autograd.Reshape(q, b, kv, g, t, d) // (B, kv, g, T, d)
k = autograd.Reshape(k, b, kv, 1, t, d) // (B, kv, 1, T, d) — broadcast по g
v = autograd.Reshape(v, b, kv, 1, t, d)

scores := autograd.MatMul(q, autograd.Transpose(k, 3, 4))       // (B, kv, g, T, T)
scores = autograd.Scale(scores, float32(1/math.Sqrt(float64(d)))) // ÷ √d_head
scores = autograd.Add(scores, autograd.NewVar(CausalMask(t, t)))  // + маска (T, T), broadcast
att := autograd.Softmax(scores)                                   // строки суммируются в 1

y := autograd.MatMul(att, v)        // (B, kv, g, T, d)
y = autograd.Reshape(y, b, h, t, d) // (B, h, T, d)
y = autograd.Transpose(y, 1, 2)     // (B, T, h, d)
y = autograd.Reshape(y, b, t, h*d)  // (B, T, C) — «concat»
return a.O.Forward(y)               // (B, T, C)
```

Backward писать не нужно: каждая операция — из `autograd`, их backward проверены (L3–L4), а формулы

`CausalMask(tq, tk)` с выравниванием по правому краю. В L10 добавим в структуру кэш K/V: новые k, v

## 13. Из продакшена

- **Не пишут attention руками.** PyTorch: `F.scaled_dot_product_attention` сам выбирает FlashAttention / memory-
  efficient ядро. Флаг `is_causal=True` вместо явной маски — ядро просто не считает верхний треугольник
  (экономия ~2× FLOPs).
- **Слитая QKV-проекция.** У GPT-2 одна матрица `c_attn` (768 × 2304) вместо трёх: один большой matmul быстрее
  трёх маленьких. Параметров столько же; при загрузке весов в L12 её режут на три.
- **Softmax в fp32.** Даже в bf16-моделях скоры и softmax считают с накоплением в fp32 (ядра FlashAttention так
  и делают).
- **Стабилизация скоров.** Gemma 2 ограничивает логиты attention через tanh (soft-capping); ряд моделей
  (например, OLMo 2, Qwen3) нормирует q и k (QK-norm), чтобы скоры не взрывались при обучении больших моделей.
- **KV-cache — главный потребитель памяти инференса.** vLLM хранит его страницами (PagedAttention, L14), как
  виртуальная память ОС; GQA/MQA, квантизация кэша в int8/fp8 и sliding window — всё ради него.
- **Типичные баги:** забыли маску при обучении (loss подозрительно быстро падает почти до 0 — модель копирует
  ответ); маска «с другой стороны» (`j < i` вместо `j > i`); softmax не по той оси (по столбцам — строки не
  суммируются в 1); √d_model вместо √d_head.

```go
package attention

import (
	"math"

	"algorithms_and_data_structures/algorythm/attention/linalg"
)

// Attention is single-head scaled dot-product attention over fixed keys and values.
//
//	Weights = softmax(Q·Kᵀ / √d_k + mask)   (n_q × n_k), every row sums to 1
//	Output  = Weights · V                   (n_q × d_v)
type Attention struct {
	Keys   linalg.Matrix // n_k × d_k
	Values linalg.Matrix // n_k × d_v
	Causal bool          // query i must not see keys after its own position
}

func (a *Attention) Calculate(query linalg.Matrix) linalg.Matrix {
	return linalg.MatMul(a.Weights(query), a.Values)
}

// Weights returns the attention matrix (n_q × n_k).
func (a *Attention) Weights(query linalg.Matrix) linalg.Matrix {
	dk := a.Keys.Cols() // √d_k of *these* keys, not a hard-coded 128
	scores := linalg.MatMul(query, a.Keys.Transpose()).Divide(math.Sqrt(float64(dk)))
	if a.Causal {
		// Queries are the last n_q positions: query i sits at position offset+i.
		offset := a.Keys.Rows() - query.Rows()
		for i := range scores {
			for j := offset + i + 1; j < len(scores[i]); j++ {
				scores[i][j] = math.Inf(-1) // exp(−∞) = 0 exactly
			}
		}
	}
	return scores.MapRows(softmax)
}

// softmax is numerically stable: subtracting the row max does not change the result
// (L2) but keeps exp from overflowing.
func softmax(z linalg.Vector) linalg.Vector {
	e := z.SubScalar(z.Max()).Map(math.Exp)
	return e.DivScalar(e.Sum())
}
```

		Keys:   linalg.Matrix{{1, 0}, {0, 2}},
		Values: linalg.Matrix{{2, 0}, {0, 6}},
		Causal: causal,
	}
}

var query = linalg.Matrix{{0, 1}, {2, 0}}

func TestRowsSumToOne(t *testing.T) {
	for _, causal := range []bool{false, true} {
		for i, row := range itWorks(causal).Weights(query) {
			if math.Abs(row.Sum()-1) > 1e-12 {
				t.Fatalf("causal=%v row %d sums to %v", causal, i, row.Sum())
			}
		}
	}
}

func TestItWorksExample(t *testing.T) {
	w := itWorks(false).Weights(query)
	// scores [0, 2]/√2 = [0, 1.414] → softmax [0.1956, 0.8044] (≈ 0.19 / 0.81 in the notes)
	if math.Abs(w[0][0]-0.19) > 0.01 || math.Abs(w[0][1]-0.81) > 0.01 {
		t.Fatalf("weights of 'it' = %v, want ≈ [0.19 0.81]", w[0])
	}
	if math.Abs(w[0][0]-0.1956) > 1e-4 {
		t.Fatalf("exact weight %v, want 0.1956", w[0][0])
	}
	out := itWorks(false).Calculate(query)
	if math.Abs(out[0][0]-0.3911) > 1e-4 || math.Abs(out[0][1]-4.8266) > 1e-4 {
		t.Fatalf("output of 'it' = %v, want [0.3911 4.8266]", out[0])
	}
}

func TestFutureWeightsAreZero(t *testing.T) {
	w := itWorks(true).Weights(query)
	if w[0][1] != 0 || w[0][0] != 1 {
		t.Fatalf("'it' must see only itself: %v", w[0])
	}
	// One query after the full prefix (decode step) sees every key.
	last := itWorks(true).Weights(linalg.Matrix{{2, 0}})
	if last[0][0] == 0 || last[0][1] == 0 {
		t.Fatalf("last query must see all keys: %v", last[0])
	}
}

1. Ответ — смесь всех значений с весами по похожести q·k. Argmax недифференцируем (градиент 0 или не определён),
   softmax — гладкий, через него учатся W_Q, W_K, W_V.
2. Q: (B, h, T, d), K, V: (B, h_kv, T, d), S и A: (B, h, T, T), O: (B, h, T, d), Y: (B, T, C), d = C/h.
3. Модель учится на всех позициях сразу; без маски токен t видит ответ t+1. e^{−∞} = 0 — ровно ноль утечки и
   нормировка сохраняется. Полностью замаскированная строка → 0/0 = NaN; поэтому в fp16/bf16 используют
   конечный минимум типа.
4. По правилу частного: aᵢ(1−aᵢ) на диагонали, −aᵢaⱼ вне. Сумма строки = aᵢ − aᵢΣⱼaⱼ = 0: сумма выходов
   всегда 1, никакое изменение входа её не меняет.
5. dV = Aᵀ·dO; dA = dO·Vᵀ; dS = A ⊙ (dA − rowsum(dA ⊙ A)); dQ = dS·K/√d; dK = dSᵀ·Q/√d.
6. b_K сдвигает все скоры строки i на qᵢ·b_K; softmax инвариантен к сдвигу строки; формально градиент

7. Параметры — 4 матрицы C × C при любом h; FLOPs скоров — h·2T²·(C/h) = 2T²C. Головы делят ширину.
