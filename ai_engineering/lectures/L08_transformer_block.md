## 1. Зачем это нужно

У нас есть все детали: эмбеддинги и позиции (L6), attention (L7), Linear, GELU, cross-entropy, AdamW (L3–L4).
Осталось собрать их так, чтобы модель из **десятков** слоёв **обучалась** — это главная трудность. Наивно
сложенные 24 слоя attention + MLP не учатся: градиенты затухают или взрываются (L4, раздел 4). Три приёма,
которые это чинят, — residual-связи, нормализация и правильная инициализация — и есть содержание этой лекции.

```
 L6 эмбеддинги ─► L7 attention ─► [L8: блок, GPT, параметры/FLOPs] ─► L9 обучение ─► L10 генерация
                                    ▲ вы здесь
```

Инженерный результат лекции: по конфигу модели вы считаете **в уме** число параметров, память под обучение и
инференс, FLOPs на токен — и сверяете с карточкой модели. Это первое, что делают перед тем, как арендовать GPU.

## 2. Residual stream: шина данных

### 2.1. Схема

```
 x₀ = эмбеддинг + позиция                                       (B, T, d)
 │
 ├──────────────┐
 │        Norm → Attention                     каждый подслой ЧИТАЕТ нормированную копию шины
 │◄─────── + ───┘                              и ДОБАВЛЯЕТ результат обратно
 ├──────────────┐
 │        Norm → FFN
 │◄─────── + ───┘
 │   … × L блоков …
 ▼
 Norm → LM head → логиты                                        (B, T, V)
```

$$\mathbf{x}_{l+1} = \mathbf{x}_l + f_l(\text{Norm}(\mathbf{x}_l)) \quad\Longrightarrow\quad \mathbf{x}_L = \mathbf{x}_0 + \sum_{l=0}^{L-1} f_l(\cdot)$$

**Интерпретация** (Elhage et al., 2021): residual stream — это **общая шина** шириной d. Ни один слой не
«заменяет» представление — каждый **дописывает** свой вклад в общую сумму. Attention переносит информацию между
позициями, FFN обрабатывает её на месте, LM head читает итог. Разные слои могут писать в разные
подпространства шины и не мешать друг другу.

### 2.2. Почему это спасает градиенты

### 🔍 Формула под лупой: производная через residual

Для одного (скалярного, для наглядности) шага x_{l+1} = x_l + f(x_l):

$$\frac{\partial x_{l+1}}{\partial x_l} = 1 + f'(x_l), \qquad \frac{\partial x_L}{\partial x_0} = \prod_{l} \big(1 + f'_l\big)$$

| Множитель | Смысл |
|---|---|
| 1 | «прямой провод» — градиент идёт по шине мимо слоя без изменений |
| f'_l | вклад самого слоя |

**Числа, 10 слоёв.** Пусть f'_l чередуются: +0.1, −0.1, +0.1, … (небольшие, как при хорошей инициализации).
- **Без residual** (x_{l+1} = f(x_l)): производная = Π f'_l, |0.1|¹⁰ = **10⁻¹⁰** — градиент до первых слоёв не
  доходит.
- **С residual:** (1.1·0.9)⁵ = 0.99⁵ = **0.951** — почти без потерь.

Даже при f' = 0.5 во всех слоях без residual 0.5¹⁰ ≈ 0.001. С residual путь «по шине» всегда даёт слагаемое 1:
раскрыв произведение, ∂x_L/∂x₀ = 1 + Σf'_l + … — градиент **никогда** не может исчезнуть полностью.

**Плата:** дисперсия шины растёт: каждый из 2L подслоёв добавляет свою случайную величину, Var(x_L) ≈ Var(x₀) +
Σ Var(f_l). Поэтому GPT-2 инициализирует **выходные** проекции подслоёв (W_O в attention и W_down в FFN) с
std = 0.02/√(2L) — тогда суммарная добавка дисперсии от 2L слоёв ≈ одной (в `gpt.Config.blockConfig` это `OutStd`).

## 3. Нормализация: LayerNorm и RMSNorm

### 3.1. Зачем

Подслою удобно получать вход **фиксированного масштаба**: GELU, softmax и √d_k рассчитаны на значения ~1 (L1, L4).
Шина же растёт по ходу сети. Нормализация приводит каждый вектор-токен к масштабу 1, **не трогая** саму шину.

### 🔍 Формула под лупой: LayerNorm

Для одного токена **x** ∈ ℝᵈ (нормализуем **по признакам** — последней оси, каждый токен отдельно):

$$\mu = \frac{1}{d}\sum_i x_i, \quad \sigma^2 = \frac{1}{d}\sum_i (x_i - \mu)^2, \quad \hat{x}_i = \frac{x_i - \mu}{\sqrt{\sigma^2 + \varepsilon}}, \quad y_i = g_i\,\hat{x}_i + b_i$$

| Символ | Форма | Смысл |
|---|---|---|
| μ, σ² | число на токен | среднее и дисперсия признаков токена |
| ε | число (10⁻⁵) | защита от деления на 0 для «нулевого» вектора |
| x̂ | (d) | среднее 0, дисперсия 1 |
| g, b | (d), обучаемые | gain и shift: вернуть модели нужный масштаб и сдвиг (init g = 1, b = 0) |

**Числа** (ε ≈ 0): **x** = [1, 2, 3, 6].
```
 μ  = (1 + 2 + 3 + 6)/4 = 3
 σ² = ((−2)² + (−1)² + 0² + 3²)/4 = (4 + 1 + 0 + 9)/4 = 3.5,   σ = 1.8708
 x̂  = [−2, −1, 0, 3]/1.8708 = [−1.0690, −0.5345, 0, 1.6036]
```
Проверка: сумма x̂ = 0 ✓, сумма квадратов = 1.1429 + 0.2857 + 0 + 2.5714 = 4 = d ✓ (дисперсия 1).

### 🔍 Формула под лупой: RMSNorm

Zhang & Sennrich (2019): центрирование почти ничего не даёт — достаточно привести к единичной **средней
квадратичной** норме:

$$r = \sqrt{\frac{1}{d}\sum_i x_i^2 + \varepsilon}, \qquad \hat{x}_i = \frac{x_i}{r}, \qquad y_i = g_i\,\hat{x}_i$$

**Числа:** mean(x²) = (1 + 4 + 9 + 36)/4 = 12.5, r = √12.5 = 3.5355, x̂ = [0.2828, 0.5657, 0.8485, 1.6971].

**Отличия:** нет μ (одна редукция вместо двух — быстрее), нет b (на 1 вектор параметров меньше), x̂ не
центрирован. Качество на практике то же. Llama, Mistral, Qwen, Gemma — RMSNorm; GPT-2 — LayerNorm.

### 3.2. Backward нормализации

Норма — не поэлементная функция: каждый выход зависит от **всех** входов через μ и σ. Выведем для RMSNorm (короче),
затем запишем LayerNorm.

### 🔍 Вывод: backward RMSNorm

Обозначим dx̂ = dy ⊙ g (градиент до умножения на gain; dg = Σ_токены dy ⊙ x̂ — как у обычного Mul).
x̂ᵢ = xᵢ/r, r = √(Σₖxₖ²/d + ε). Сначала ∂r/∂xⱼ = (1/(2r))·(2xⱼ/d) = xⱼ/(d·r). Теперь по правилу частного:

$$\frac{\partial \hat{x}_i}{\partial x_j} = \frac{\delta_{ij}}{r} - \frac{x_i}{r^2}\cdot\frac{x_j}{d\,r} = \frac{1}{r}\Big(\delta_{ij} - \frac{\hat{x}_i \hat{x}_j}{d}\Big)$$

Цепное правило (сумма по всем выходам i, L3):

$$dx_j = \sum_i dx̂_i\,\frac{\partial \hat{x}_i}{\partial x_j} = \frac{1}{r}\Big(dx̂_j - \hat{x}_j\cdot\underbrace{\frac{1}{d}\sum_i dx̂_i\,\hat{x}_i}_{\text{mean}(dx̂ \odot \hat{x})}\Big)$$

Для **LayerNorm** добавляется ещё вычитание среднего (производная от μ), и получается:

$$\boxed{dx = \frac{1}{\sigma}\Big(dx̂ - \text{mean}(dx̂) - \hat{x}\odot\text{mean}(dx̂\odot\hat{x})\Big)} \qquad \text{RMSNorm: то же без } \text{mean}(dx̂),\ \sigma \to r$$

**Числа.** **x** = [1, 2, 3, 6], g = 1, и пусть loss зависит только от последнего выхода: dy = [0, 0, 0, 1].

*LayerNorm:* dx̂ = [0, 0, 0, 1]; mean(dx̂) = 0.25; mean(dx̂ ⊙ x̂) = 1.6036/4 = 0.4009.
```
 dx₀ = (0 − 0.25 − (−1.0690)·0.4009)/1.8708 = ( 0.1786)/1.8708 =  0.0955
 dx₁ = (0 − 0.25 − (−0.5345)·0.4009)/1.8708 = (−0.0357)/1.8708 = −0.0191
 dx₂ = (0 − 0.25 − 0)/1.8708                 = (−0.25)  /1.8708 = −0.1336
 dx₃ = (1 − 0.25 − 1.6036·0.4009)/1.8708     = ( 0.1071)/1.8708 =  0.0573
```
Градиент получили **все** входы, хотя loss смотрел только на y₃: x₀ влияет на y₃ через μ и σ. Сумма dx = 0 —
сдвиг всех xᵢ на константу выход LayerNorm не меняет.

*RMSNorm:* mean(dx̂ ⊙ x̂) = 1.6971/4 = 0.4243; x̂ ⊙ 0.4243 = [0.12, 0.24, 0.36, 0.72].
```
 dx = ([0, 0, 0, 1] − [0.12, 0.24, 0.36, 0.72]) / 3.5355 = [−0.0339, −0.0679, −0.1018, 0.0792]
```
Проверка: dx · x = −0.0339 − 0.1358 − 0.3054 + 0.4752 ≈ 0 — градиент перпендикулярен x, потому что
RMSNorm(c·x) = RMSNorm(x): растяжение вдоль x ничего не меняет, производная в этом направлении — 0.

Тест `TestNormLectureExample` проверяет эти числа; `TestNormsMatchComposite` — что слитые `autograd.LayerNorm` /
`autograd.RMSNorm` совпадают с той же формулой, собранной из примитивов (MeanLast, Sub, Pow, …);
`TestGradCheckTransformerOps` — backward конечными разностями.

**Зачем слитая операция,** если можно собрать из примитивов: из примитивов получается ~7 узлов графа, каждый
выделяет тензор (B, T, d) и проходит по памяти. Слитая — один проход вперёд и один назад. На GPU разница ещё
больше (норма — memory-bound операция, L14).

### 3.3. Pre-LN vs Post-LN

```
 Post-LN (Vaswani 2017, BERT):   x = Norm(x + f(x))         норма СТОИТ НА ШИНЕ
 Pre-LN  (GPT-2 и далее):        x = x + f(Norm(x))         шина «чистая», норма — только на входе подслоя
                                 + финальная Norm перед LM head
```

**Почему Pre-LN обучается стабильнее** (Xiong et al., 2020):
- В Post-LN градиент к ранним слоям проходит через L норм, каждая из которых масштабирует его (backward нормы —
  деление на σ, раздел 3.2). «Прямого провода» с множителем 1 нет — residual-эффект из раздела 2.2 частично
  теряется.
- Xiong et al. показали: в Post-LN при инициализации градиенты параметров **последних** слоёв велики, поэтому
  без долгого **warmup** learning rate обучение расходится. В Pre-LN градиенты хорошо обусловлены, warmup можно
  сократить или убрать.
- Цена Pre-LN: шина растёт по ходу сети (её никто не нормирует), поздние слои вносят относительно меньший вклад;
  отсюда обязательная **финальная** норма перед LM head.

GPT-2 перенесла нормализацию на вход подблоков и добавила финальную норму — с тех пор Pre-LN (с RMSNorm у Llama) —
стандарт. Абляцию Post-LN vs Pre-LN сделаете в задании 🔴 9.

## 4. FFN: 4×, GELU, SwiGLU

### 4.1. Классический FFN (GPT-2)

$$\text{FFN}(\mathbf{x}) = \text{GELU}(\mathbf{x}W_{up} + \mathbf{b}_1)\,W_{down} + \mathbf{b}_2, \qquad W_{up}: (d, 4d),\ W_{down}: (4d, d)$$

Каждый токен **отдельно**: (B, T, d) → (B, T, 4d) → (B, T, d). Параметров 8d² (+ 5d смещений) — **в 2 раза
больше**, чем у attention (4d²). Две трети параметров блока — в FFN.

**Почему 4×** — эмпирический выбор Vaswani et al. (d = 512, d_ff = 2048), закрепившийся по инерции. Шире —
больше «памяти» (раздел 4.3), но дороже.

**GELU** (Hendrycks & Gimpel, 2016): x·Φ(x), где Φ — функция распределения N(0, 1): «пропустить x с вероятностью,
что N(0,1) < x». GPT-2 использует tanh-приближение (`autograd.GELU`, L4):

| x | −3 | −1 | −0.5 | 0 | 0.5 | 1 | 3 |
|---|---|---|---|---|---|---|---|
| ReLU | 0 | 0 | 0 | 0 | 0.5 | 1 | 3 |
| GELU (tanh) | −0.0036 | −0.1588 | −0.1543 | 0 | 0.3457 | 0.8412 | 2.9964 |
| SiLU = x·σ(x) | −0.1423 | −0.2689 | −0.1888 | 0 | 0.3112 | 0.7311 | 2.8577 |

Гладкая версия ReLU: немного пропускает отрицательные значения, производная нигде не равна нулю скачком —
меньше «мёртвых» нейронов.

### 4.2. SwiGLU и откуда 8/3

Shazeer (2020), «GLU Variants Improve Transformer»: заменить «активацию от одной проекции» на **гейт** — поэлементное
произведение двух проекций, одна из которых прошла через нелинейность:

### 🔍 Формула под лупой: SwiGLU

$$\text{SwiGLU}(\mathbf{x}) = \big(\text{SiLU}(\mathbf{x}W_{gate}) \odot \mathbf{x}W_{up}\big)\,W_{down}$$

| Символ | Форма | Смысл |
|---|---|---|
| xW_gate | (f) | «насколько открыть» каждый из f каналов |
| SiLU | поэлементно | x·σ(x) — мягкий гейт (≈ 0 для отрицательных, ≈ x для положительных) |
| xW_up | (f) | «что пропустить» |
| ⊙ | | поэлементное умножение: значение × степень открытия |
| W_down | (f, d) | обратно в ширину шины |

**Числа** (f = 2): xW_gate = [1, −2], xW_up = [3, 0.5].
SiLU(1) = 1·σ(1) = 0.7311; SiLU(−2) = −2·σ(−2) = −2·0.1192 = −0.2384.
Гейт ⊙ значение = [0.7311·3, −0.2384·0.5] = **[2.1932, −0.1192]**: первый канал открыт, второй почти закрыт.

**Почему лучше** — честно: Shazeer показал улучшение perplexity экспериментально и прямо написал, что
объяснения не предлагает. Интуиция: произведение двух линейных функций даёт модели **квадратичные**
взаимодействия признаков (x_i·x_j) в одном слое; гейт решает, какие каналы активны, независимо от того, что
они несут.

### 🔍 Вывод: коэффициент 8/3

У SwiGLU **три** матрицы d × f вместо двух. Чтобы сравнение с FFN 4d было честным (одинаковые параметры и FLOPs):

$$3\,d\,f = 2\,d\,(4d) = 8d^2 \quad\Longrightarrow\quad f = \frac{8}{3}\,d$$

Для d = 4096: f = 10 922.67. Округляют вверх до кратного 256 (удобно для GPU): **11 008** — ровно d_ff у
Llama-2-7B. Llama 3 добавила множитель 1.3 и кратность 1024: int(1.3 · 10 922) = 14 198 → **14 336** (у Llama-3-8B
f = 3.5d, FFN «толще» классического). В коде — `gpt.SwiGLUHidden(d, multiple)`.

### 4.3. FFN как key-value память

Geva et al. (2021): запишем FFN через строки и столбцы. Пусть **k**ᵢ — i-й **столбец** W_up, **v**ᵢ — i-я **строка**
W_down. Тогда

$$\text{FFN}(\mathbf{x}) = \sum_{i=1}^{f} \text{act}(\mathbf{x}\cdot\mathbf{k}_i)\;\mathbf{v}_i$$

Это тот же «мягкий словарь», что attention (L7), только ключи и значения — **выученные константы**, а не токены
контекста, и вместо softmax — поэлементная активация. Каждый «нейрон» i — детектор паттерна **k**ᵢ, который при
срабатывании дописывает в шину вектор **v**ᵢ.

**Пример** (f = 2, ReLU): **k**₁ = [1, 0], **k**₂ = [0, 1]; **v**₁ = [2, 0], **v**₂ = [0, −1]; **x** = [3, −1].
x·k₁ = 3 → ReLU 3; x·k₂ = −1 → ReLU 0. Выход = 3·[2, 0] + 0·[0, −1] = **[6, 0]**: сработал только первый
детектор.

Geva et al. нашли, что ключи нижних слоёв реагируют на поверхностные паттерны (конкретные слова), верхних —
на смысловые, а значения сдвигают распределение следующего токена. Meng et al. (2022, ROME) показали, что
**отредактировав** одну такую «ячейку» в средних слоях, можно поменять факт («Эйфелева башня находится в …»).
Отсюда популярная формула: **attention перемещает информацию, FFN хранит знания**.

## 5. Блок и GPT целиком

```go
// nn.Block — Pre-LN
func (b *Block) Forward(x *autograd.Var, pos int) *autograd.Var {
	x = autograd.Add(x, b.Attn.Forward(b.Norm1.Forward(x), pos)) // (B, T, d)
	return autograd.Add(x, b.FFN.Forward(b.Norm2.Forward(x)))    // (B, T, d)
}
```

```go
// gpt.Model.ForwardAt — вся модель
x := m.Tok.ForwardBatch(ids)                 // (B, T) → (B, T, d)
x = x + позиции (learned / sinusoidal)       // RoPE — внутри attention
for _, b := range m.Blocks { x = b.Forward(x, pos) } // L × (B, T, d)
x = m.NormF.Forward(x)                       // (B, T, d)
logits = x·W_head  или  x·Tokᵀ (tied)        // (B, T, V)
```

### GPT-2 vs Llama: таблица отличий

| | GPT-2 (2019) | Llama 2 (2023) | Llama 3 (2024) |
|---|---|---|---|
| Позиции | обучаемые, 1024 | RoPE, base 10⁴ | RoPE, base 5·10⁵ |
| Нормализация | LayerNorm (g, b), Pre-LN | RMSNorm (g), Pre-LN | RMSNorm, Pre-LN |
| FFN | GELU, 4d | SwiGLU, ≈ 8/3·d (11 008) | SwiGLU, 3.5d (14 336) |
| Смещения в Linear | да | нет | нет |
| Attention | MHA | MHA (7B, 13B), GQA (70B) | GQA, 8 K/V-голов |
| LM head | связан с эмбеддингом | отдельный | отдельный (8B, 70B) |
| Словарь | 50 257 (BPE по байтам) | 32 000 (SentencePiece) | 128 256 (tiktoken-подобный BPE) |
| Контекст | 1 024 | 4 096 | 8 192 (3.1: 128K) |
| Dropout | 0.1 | нет | нет |

Почти каждое отличие уже разобрано: RoPE (L6), GQA (L7), RMSNorm и SwiGLU (выше). Тренд — **убрать лишнее**
(смещения, центрирование, dropout при одной эпохе по огромным данным) и **сэкономить на инференсе** (GQA).

```go
gpt.Llama3_8B  // Pos: PosRoPE,    Norm: NormRMS,   FFN: FFNSwiGLU, Bias: false, KVHeads: 8
gpt.TinyGPT2(V, ctx), gpt.TinyLlama(V, ctx) // d = 32, L = 2, h = 4 — для CPU
```

## 6. Подсчёт параметров

### 🔍 Вывод: 12·L·d² + V·d

Один блок GPT-2-стиля (MHA, FFN 4d), только матрицы:

| Часть | Матрицы | Параметров |
|---|---|---|
| W_Q, W_K, W_V | 3 × (d, d) | 3d² |
| W_O | (d, d) | d² |
| W_up | (d, 4d) | 4d² |
| W_down | (4d, d) | 4d² |
| **итого на слой** | | **12d²** |

Плюс эмбеддинг V × d (с tied head — один раз). Всё остальное — векторы длины ~d: смещения (4d в attention,
4d + d в FFN) и две LayerNorm (2·2d) = 13d на слой; позиции T_max·d; финальная норма 2d.

$$N \approx 12\,L\,d^2 + V\,d$$

### Проверка: GPT-2 small (L = 12, d = 768, V = 50 257)

```
 12·L·d²            = 12 · 12 · 589 824       =  84 934 656
 V·d                = 50 257 · 768             =  38 597 376
 приближение                                   = 123 532 032   (99.3 % точного)
 ─── уточнение ───
 13d на слой × 12   = 9 984 · 12               =     119 808
 позиции 1024·768                              =     786 432
 финальная LayerNorm 2·768                     =       1 536
 ИТОГО                                         = 124 439 808   ✓ ровно столько у GPT-2 в Hugging Face
```

### Llama: формула ломается — и это поучительно

**Llama-2-7B** (d = 4096, L = 32, V = 32 000, f = 11 008, без смещений, untied):
```
 attention 4d²                      =  67 108 864
 SwiGLU 3·d·f = 3·4096·11 008       = 135 266 304   (а не 8d² = 134 217 728: f округлили вверх)
 2 RMSNorm 2d                       =       8 192
 на слой                            = 202 383 360   × 32 = 6 476 267 520
 эмбеддинг + head 2·V·d             = 262 144 000   (head не связан → V·d дважды)
 финальная норма                    =       4 096
 ИТОГО                              = 6 738 415 616  ✓ (6.74B)
```
Формула 12Ld² + Vd дала бы 6.57B (97.6 %): не учтены второй V·d и округление f.

**Llama-3-8B** (h_kv = 8 → K, V: (d, 1024); f = 14 336; V = 128 256):

## 7. FLOPs: 2N на токен, 6ND на обучение

### 🔍 Вывод: почему 2N и 6N

**Forward.** Каждый вес матрицы участвует в обработке токена ровно в одном умножении и одном сложении
(y_j += x_i·W_ij). Значит, на токен — **2 FLOP на параметр**: 2N. (Эмбеддинг — lookup, 0 FLOP; LM head — matmul,
2Vd — его надо учитывать, даже если он связан с эмбеддингом.)

**Backward.** Для каждого matmul Y = X·W нужно **два** matmul той же стоимости: dX = dY·Wᵀ (передать градиент
дальше) и dW = Xᵀ·dY (градиент весов) — L3. Итого 4N на токен.

$$C_{train} \approx (2 + 4)\,N\,D = 6ND$$

Плюс attention-матрицы (L7, раздел 9): на токен 4·L·T·d в forward (2·L·T·d с учётом causal-маски — так у
Kaplan et al.).

**Числа:**

| Модель | 2N | forward на токен с attention (полный контекст) |
|---|---|---|
| GPT-2 124M, T = 1024 | 2.49·10⁸ | 2.85·10⁸ |
| Llama-3-8B, T = 8192 | 1.61·10¹⁰ | 1.93·10¹⁰ |

**Обучение Llama-3-8B** на 15·10¹² токенов (так сообщает Meta): 6 · 8.03·10⁹ · 1.5·10¹³ ≈ **7.2·10²³ FLOP**.
Это ~1 870 токенов на параметр — в 90+ раз больше «Chinchilla-оптимальных» 20 токенов на параметр (L11):
модель намеренно «перекормлена», чтобы быть сильнее при фиксированной стоимости **инференса**.

**Инференс — упирается в память, а не в FLOPs.** Генерация одного токена при батче 1 читает **все** веса:
Llama-3-8B в bf16 — 16.06 ГБ. При пропускной способности HBM у H100 SXM 3.35 ТБ/с это ≥ 4.8 мс на токен, то
есть **≤ ~210 токенов/с** — при том что 1.6·10¹⁰ FLOP GPU с ~10¹⁵ FLOP/с посчитал бы за 16 мкс. Поэтому
инференс батчат (L14): одно чтение весов — на много запросов.

## 8. Память обучения

### 🔍 Формула под лупой: 16 байт на параметр

Обучение в смешанной точности с Adam (Rajbhandari et al., 2019, ZeRO):

| Что | Байт / параметр | Зачем |
|---|---|---|
| веса bf16 | 2 | forward/backward |
| градиенты bf16 | 2 | результат backward |
| мастер-копия весов fp32 | 4 | маленькие обновления lr·g теряются в bf16 (L3) |
| Adam m, v в fp32 | 4 + 4 | моменты (L3, раздел 6) |
| **итого** | **16** | |

GPT-2 124M: 16 · 124.4·10⁶ = **1.85 ГиБ**. Llama-3-8B: 16 · 8.03·10⁹ = **119.7 ГиБ** — больше, чем 80 ГБ одного
H100, ещё **до** активаций. Поэтому даже 8B учат на многих GPU с шардированием состояний (ZeRO/FSDP, L11).

**Активации** — промежуточные тензоры, сохранённые для backward. Оценка Korthikanti et al. (2022) для блока
GPT-типа (16-битные активации, dropout, без перевычисления):

$$\text{на слой: } s\cdot b\cdot d\cdot\Big(34 + 5\,\frac{h\,s}{d}\Big) \text{ байт}$$

| Символ | Смысл |
|---|---|
| s, b | длина последовательности, батч |
| 34·s·b·d | линейные по T тензоры: входы норм, Q, K, V, выход FFN 4d, маски dropout … |
| 5·h·s²·b | матрицы внимания (B, h, T, T): скоры, softmax, маска dropout — квадратичные по T |

GPT-2, s = 1024, b = 1: 1024·768·(34 + 5·12·1024/768) = 786 432 · 114 = 89.7 МБ на слой, × 12 = **1.0 ГиБ на
одну последовательность** — сопоставимо со всем состоянием модели и оптимизатора (1.85 ГиБ), а при батче 32 —
32 ГиБ, в 17 раз больше него.
Для Llama-3-8B на 8K формула даёт 354 ГиБ на последовательность — без FlashAttention (не хранит T²) и
**activation checkpointing** (пересчитывать активации в backward вместо хранения) такие модели не обучить.

Калькулятор: `gpt.Config.Memory()`, `ActivationBytes(batch, seq)`.

## 9. Loss на старте ≈ ln V

### 🔍 Вывод

При инициализации модель ничего не знает, и логиты почти одинаковы → softmax почти равномерный → вероятность
правильного токена ≈ 1/V:

$$L_0 = -\ln p_{target} \approx -\ln\frac{1}{V} = \ln V$$

**Поправка на ненулевые логиты.** У GPT-2-инициализации логит = (выход финальной нормы, дисперсия ≈ 1 на
компоненту) · (строка эмбеддинга, std 0.02): z ~ N(0, σ²) с σ = 0.02·√d. Для гауссовых z: E[e^z] = e^{σ²/2}, так что

$$L_0 = \mathbb{E}\Big[\ln\sum_j e^{z_j} - z_t\Big] \approx \ln\big(V\,e^{\sigma^2/2}\big) - 0 = \ln V + \frac{\sigma^2}{2}$$

| Модель | V | ln V | σ = 0.02√d | прогноз ln V + σ²/2 | измерено (наш Go-код) |
|---|---|---|---|---|---|
| tiny (d = 32) | 64 | 4.159 | 0.113 | 4.165 | 4.17–4.19 (тест `TestInitialLossIsLnV`, 4 архитектуры) |
| GPT-2 124M (d = 768) | 50 257 | 10.825 | 0.554 | 10.979 | 10.944 (`gpt.New(rng, GPT2Small)`, 32 случайных токена) |

**Зачем это проверять.** Если loss на старте **намного больше** ln V (скажем, 30 вместо 10.8) — логиты
слишком большие: модель «уверенно ошибается», первые сотни шагов уйдут на то, чтобы просто сжать логиты
(«хоккейная клюшка» на кривой loss). Если **меньше** ln V — подозрительно: утечка ответа (забыли causal-маску,
сдвиг targets на 1) или баг в loss. Это первая строка рецепта Karpathy.

## 10. Sanity-check: переобучить один батч

Вторая строка рецепта: возьмите **один** маленький батч и учите только на нём. Модель с десятками тысяч
параметров обязана выучить 24 токена наизусть — loss → 0. Если нет — сломано что-то в forward, backward,
маске или оптимизаторе; искать баги на полном датасете бессмысленно.

Тест `TestOverfitSingleBatch`: 2 последовательности по 12 случайных токенов (V = 32), targets = ids со сдвигом
на 1, AdamW lr = 10⁻², clip 1.0. Реальный вывод:

| шаг | tiny-gpt2 (26 880 параметров) | tiny-llama (25 248 параметров) |
|---|---|---|
| 0 | 3.483 (ln 32 = 3.466 ✓) | 3.461 |
| 25 | 0.0517 | 0.0253 |
| 50 | 0.0017 | 0.0011 |
| 149 | 0.0002 | 0.0002 |

Время — ~0.2 с на 150 шагов для каждой модели на Apple M5 Pro. Цикл — ровно шаг обучения из L3:

```go
opt := optim.NewAdamW(ps, 1e-2, 0)
for step := range 150 {
	opt.ZeroGrad()
	loss := m.Loss(ids, targets) // ids, targets: (B, T); targets = ids, сдвинутые на 1
	loss.Backward()
	optim.ClipGradNorm(ps, 1)
	opt.Step()
}
```

Обратите внимание: токены **случайные** — никакой закономерности нет, это чистое запоминание. Почему модель
вообще может их запомнить, если токен на позиции t видит только ≤ t? Позиции различимы (learned/RoPE), и в батче
нет двух одинаковых префиксов — значит, «префикс → следующий токен» — функция, которую сеть может выучить.

### `autograd` (новые операции, все с GradCheck)

| Операция | Формы | Backward |

## 12. Из продакшена

- **Калькулятор до GPU.** Перед любым запуском считают: влезет ли состояние (16 Б/параметр + активации), сколько
  займёт обучение (6ND / (число GPU · пиковые FLOP/с · MFU)). MFU (доля пика) у хороших реализаций — 35–55 %.
- **Округление размерностей.** d_ff кратно 256/1024, V дополняют до кратного 64/128 (nanoGPT: 50 257 → 50 304) —
  ради эффективности Tensor Cores (L1).
- **Параллельные блоки** (GPT-J, PaLM): x + Attn(Norm(x)) + FFN(Norm(x)) — attention и FFN считаются
  параллельно, один all-reduce вместо двух; немного быстрее, качество близко.
- **Стабильность больших моделей:** QK-norm, логит-софткэппинг (Gemma 2), z-loss на логитах (PaLM), «sandwich»-нормы
  — всё это заплатки против одного явления: отдельные логиты/активации разрастаются при обучении в bf16.
- **Сверка с карточкой модели** — лучший unit-тест конфигурации: если ваш подсчёт параметров не совпал с
  «8 030 261 248», вы неправильно поняли архитектуру (связан ли head? сколько K/V-голов? какое f?). Именно так
  в L12 будем проверять загрузку настоящих весов.
- **Где живут параметры у маленьких моделей:** у GPT-2 small эмбеддинг — 31 %, у Llama-3.2-1B (связанный head,
  словарь 128K, d = 2048) — 128 256 · 2048 ≈ 263 млн из ≈ 1.24 млрд, около 21 %; без связывания было бы вдвое
  больше. Поэтому для маленьких моделей словарь — ключевая статья бюджета (L5).

<details><summary>Ответы</summary>

1. x_{l+1} = x_l + f(x_l) → производная I + f'. В произведении по слоям всегда есть слагаемое «единица» — путь
   по шине без изменений.
2. 2L подслоёв добавляют в шину независимые вклады; дисперсии складываются. Масштаб 1/√(2L) у std (1/(2L) у
   дисперсии) держит суммарную добавку ≈ константой при любой глубине.
3. LN: (x − μ)/√(σ² + ε)·g + b; RMS: x/√(mean(x²) + ε)·g. RMS не центрирует и не имеет b; эмпирически качество
   то же — главное, что масштаб входа подслоя фиксирован; и быстрее.
4. LN инвариантна к сдвигу x + c·1 → производная вдоль 1 равна 0 → Σdx = 0. RMSNorm инвариантна к масштабу
   c·x → производная вдоль x равна 0 → dx·x = 0.
5. Post-LN: Norm(x + f(x)) — норма на шине, градиент проходит через L норм, нужен долгий warmup; Pre-LN:
   x + f(Norm(x)) — шина чистая, градиент идёт «по проводу» с множителем 1.
6. Три матрицы d×f при том же бюджете, что две матрицы d×4d: 3df = 8d² → f = 8d/3 = 10 922.67 для d = 4096,
   округление вверх до кратного 256 → 11 008.
7. FFN(x) = Σᵢ act(x·kᵢ)·vᵢ, kᵢ — столбцы W_up (детекторы паттернов), vᵢ — строки W_down (что дописать в шину).
8. Attention 4d² + FFN 8d² на слой + эмбеддинг Vd. У Llama-3-8B: GQA даёт 2.5d², SwiGLU с f = 3.5d — 10.5d²
   (итого 13d²), head не связан (+Vd), V = 128K — эмбеддинги весят 1.05B.
9. Forward: умножение + сложение на каждый вес (2N). Backward: два matmul той же стоимости — по входу и по
   весам (4N).
10. Логиты ≈ 0 → p ≈ 1/V → −ln(1/V). Намного выше — слишком большие логиты при инициализации («уверенно
    ошибается»); ниже — утечка ответа (маска, сдвиг targets) или баг в loss.

</details>
