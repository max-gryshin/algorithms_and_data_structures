# Dynamic Programming

DP разбивает задачу на **перекрывающиеся** подзадачи и заменяет полный перебор мемоизацией (top-down) или таблицей (bottom-up).

## Когда применять

- Есть **оптимальная подструктура**: решение задачи выражается через решения подзадач.
- Подзадачи **перекрываются**: наивная рекурсия многократно пересчитывает одно и то же.
- Формулировка: «найти min/max», «посчитать количество способов», «возможно ли достичь».

## Пять шагов

1. **Состояние** — что такое `dp[i]` (или `dp[i][j]`)? Отвечает на «сколько/можно ли/минимум для префикса длины i».
2. **Переход** — как `dp[i]` выражается через предыдущие состояния.
3. **База** — значения `dp[0]`, `dp[1]` и т.п.
4. **Порядок обхода** — чтобы к моменту вычисления `dp[i]` все нужные состояния уже были посчитаны.
5. **Ответ** — обычно `dp[n]` или `max(dp)` / `min(dp)`.

## Top-down vs Bottom-up

- **Top-down (мемоизация)**: рекурсия + кэш. Проще писать, естественно повторяет структуру задачи. Есть накладные расходы на стек и хеш-таблицу.
- **Bottom-up (табуляция)**: цикл + массив. Обычно быстрее, часто даёт возможность сократить память (rolling array — храним только последние 1–2 строки/значения).

## Типичные ошибки

- Плохо определённое состояние — переход получается «мутным» или неправильным. Формулируй состояние так, чтобы одна фраза его описывала.
- Неверный порядок обхода: в 0/1 knapsack по capacity нужно идти **справа налево**, иначе один предмет использ. несколько раз.
- Забыть базу или обработать `i=0`.
- Не заметить, что можно сократить память с `O(n²) → O(n)` или `O(n) → O(1)`.
- Путать «подпоследовательность» (не обязательно смежные) и «подстроку/подмассив» (смежные) — это разные задачи.

## Оценка сложности

- 1D DP: обычно `O(n)` время, `O(n)` или `O(1)` память.
- 2D DP: `O(n·m)` время, `O(n·m)` или `O(min(n,m))` память.
- LIS: наивно `O(n²)`, с бинпоиском `O(n log n)`.
- Knapsack: `O(n·W)`.
