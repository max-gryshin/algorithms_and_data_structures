# Prefix Sum

Паттерн «префиксные суммы»: предпосчитываем массив `prefix[i] = sum(nums[0..i-1])`, чтобы отвечать на range-sum запросы `sum(l..r) = prefix[r+1] - prefix[l]` за O(1).

## Когда использовать

- Много запросов `sum(l..r)` на неизменяемом массиве.
- Задача про **подмассивы**, где важна их сумма (или её остаток по модулю, или количество нечётных, и т.п.).
- В связке с HashMap: считаем, сколько префиксных сумм с нужным свойством встречалось ранее.

## Базовый шаблон

```go
prefix := make([]int, len(nums)+1)
for i, v := range nums {
    prefix[i+1] = prefix[i] + v
}
// sum(l..r) == prefix[r+1] - prefix[l]
```

## Prefix Sum + HashMap (количество подмассивов с суммой K)

Идея: если `prefix[j] - prefix[i] == k`, то подмассив `(i..j-1)` подходит. Для каждого `j` нужно количество `i` таких, что `prefix[i] == prefix[j] - k`.

```go
count := map[int]int{0: 1} // 0 — пустой префикс
sum, result := 0, 0
for _, v := range nums {
    sum += v
    result += count[sum-k]
    count[sum]++
}
```

## Prefix Sum по модулю (сумма кратная K)

`sum(l..r) mod k == 0` ⇔ `prefix[r+1] mod k == prefix[l] mod k`. Считаем, сколько раз каждый остаток встречался.

## Типичные ошибки

- Забыть `count[0] = 1` (пустой префикс) — теряем случаи, когда весь префикс подходит.
- Off-by-one в границах: `sum(l..r) = prefix[r+1] - prefix[l]`, а не `prefix[r] - prefix[l]`.
- Не привести отрицательные остатки к неотрицательным при работе `mod`.


Ход мышления при решении задач:
1. Что означает prefix[i]?
2. Как выразить свойство subarray[l..r]
   через prefix[r] и prefix[l-1]?
   «Что именно должно совпасть у двух prefix, чтобы условие задачи выполнялось?»
3. Какое условие должно выполняться
   между этими двумя prefix?
4. Что конкретно мне нужно искать
   среди предыдущих prefix?
5. Что должен хранить map,
   чтобы искать это за O(1)?
