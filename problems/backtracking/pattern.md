# Backtracking

Паттерн «перебор с возвратом»: строим решение шаг за шагом, добавляя выбор в текущее состояние. Если дальше идти некуда или выбор нарушил ограничения — откатываем (backtrack) и пробуем следующий.

## Когда использовать

- Нужно найти **все** валидные конфигурации (перестановки, подмножества, разбиения, комбинации).
- Есть чёткие ограничения (constraints), по которым можно рано отсекать ветки (pruning).
- Размер входа маленький (обычно N ≤ 20), потому что в общем случае сложность экспоненциальная.

## Шаблон

```go
func backtrack(state, choices) {
    if isSolution(state) {
        record(state)
        return
    }
    for _, choice := range validChoices(state, choices) {
        apply(choice)          // сделать выбор
        backtrack(state, choices)
        undo(choice)           // откатить выбор
    }
}
```

Три ключевых момента:
1. **Base case** — условие, что текущее состояние — готовое решение (или тупик).
2. **Choice** — цикл по вариантам следующего шага.
3. **Undo** — откат состояния после рекурсивного вызова.

## Оценка сложности

- Permutations: O(N! · N)
- Subsets: O(2^N · N)
- Combination Sum: экспоненциально от target/min(candidates)
- N-Queens: ~O(N!) с обрезаниями

## Типичные ошибки

- Забыть откат — тогда состояние «протекает» между ветками.
- Не отсекать невалидные ветки заранее — тайм-аут.
- Копировать состояние вместо мутируемого одного — теряем производительность (но копия готового решения при записи в результат обязательна: `append(res, append([]int{}, path...))`).
