# Monotonic Stack

Паттерн «монотонный стек»: поддерживаем стек, в котором элементы отсортированы (по возрастанию или убыванию). При добавлении нового элемента вытесняем всё, что нарушает монотонность.

## Когда использовать

- Найти для каждого элемента **ближайший больший/меньший** слева или справа.
- Задачи про гистограммы (максимальный прямоугольник), про накопление воды, про span'ы, про nearest smaller/greater.
- Обычно даёт O(n) там, где наивное решение O(n²).

## Шаблон (Next Greater Element справа, O(n))

```go
result := make([]int, len(nums))
for i := range result {
    result[i] = -1
}
stack := []int{} // индексы; значения по индексам монотонно НЕ убывают снизу вверх (т.е. убывают сверху вниз)
for i, v := range nums {
    for len(stack) > 0 && nums[stack[len(stack)-1]] < v {
        top := stack[len(stack)-1]
        stack = stack[:len(stack)-1]
        result[top] = v
    }
    stack = append(stack, i)
}
```

## Выбор монотонности

| Что ищем                       | Направление обхода | Монотонность стека     |
|--------------------------------|--------------------|------------------------|
| Next Greater справа            | слева направо      | убывает сверху вниз    |
| Next Smaller справа            | слева направо      | возрастает сверху вниз |
| Previous Greater слева         | слева направо      | убывает сверху вниз    |
| Previous Smaller слева         | слева направо      | возрастает сверху вниз |

## Ключевая идея

Каждый элемент кладётся в стек **один раз** и вынимается **не более одного раза** → амортизированная O(n).

## Типичные ошибки

- Хранить в стеке значения вместо индексов, когда нужно расстояние/ширина (Daily Temperatures, Largest Rectangle).
- Перепутать направление монотонности — получить противоположный ответ.
- Забыть обработать элементы, оставшиеся в стеке в конце (иногда им нужен ответ «нет» → -1, иногда нужно «выпустить пар», добавив в конец фиктивную границу).
- В circular-задачах (LC 503) забыть пройти массив дважды через `i % n`.
